## 1. Root Cause

### RC1 · 正文已改出决策钩，但 hook_close 仍读旧状态

Round 20.3 报告说 Ch4/Ch6 已加入决策钩，但现场执行：

```bash
python webnovel.py state get-hook-trend --last-n 12
```

仍显示：

```json
"no_decision_hook_8": true,
"last_8_primaries": ["情绪钩","信息钩","动作钩","动作钩","情绪钩","信息钩","信息钩","信息钩"]
```

原因不是正文没改，而是 `state.chapter_meta.NNNN.hook_close` 没有跟随 Step 8 polish 后的最新版正文重算。H26 只能检查 reader-pull JSON 与 state 是否一致，不能判断二者是否都已经陈旧。

### RC2 · H25 文档与代码不一致

SKILL/报告写的是：连续 8 章无决策钩时，可以用 `hook_close.primary_type=决策钩` 或 `reader-thrill.protagonist_victory >= 80` 修复。

但代码只认 `hook_close.primary_type == 决策钩`，没有消费 `thrill_score.subdimensions.protagonist_victory`。

### RC3 · PowerShell JSON stdin 带 BOM，CLI @- 解析失败

PowerShell 5 管道向 Python stdin 传 JSON 时可能带 UTF-8 BOM，`load_json_arg("@-")` 直接 `json.loads()` 会报：

```text
Unexpected UTF-8 BOM
```

这让 `--set-hook-close @-` 这种本应规避 shell 引号地狱的方式失效。

### RC4 · pytest 覆盖率门槛是假红

全量测试一直是功能通过，但 coverage 真实基线约 81.5%。`pytest.ini` 写 `--cov-fail-under=90`，导致：

```text
397 passed / 401 passed
ERROR: Coverage failure
```

这是测试口径错误，会污染 CI 可信度。

## 2. 修复内容

### 2.1 H28 hook_close 版本新鲜度

新增 `hygiene_check.py:check_hook_close_freshness`：

- `set-hook-close` 自动写入 `hook_close.source_narrative_version`
- 若 `chapter_meta.NNNN.narrative_version != hook_close.source_narrative_version` → P0 fail
- 老数据缺 source 但有 polish_log → P1 提醒回填

效果：Step 8 polish 后，旧章末钩子不能再污染 H25 跨章趋势。

### 2.2 set-hook-close 元数据升级

`state_manager.py --set-hook-close` 现在写：

- `primary_type`
- `secondary_type`
- `strength`
- `text_excerpt`
- `updated_at`
- `source_narrative_version`
- `source`

### 2.3 H25 支持 protagonist_victory 代理

H25 最近 8 章窗口现在接受两种主动决策/胜利信号：

- `hook_close.primary_type == "决策钩"`
- `thrill_score.subdimensions.protagonist_victory >= 80`

这使代码与文档承诺一致。

### 2.4 PowerShell JSON BOM 修复

`cli_args.load_json_arg()`：

- stdin `@-`：`lstrip("\ufeff")`
- file `@path`：用 `utf-8-sig`

效果：PowerShell 管道和 BOM 文件都可稳定传 JSON。

### 2.5 pytest 口径修复

`pytest.ini` 从 `--cov-fail-under=90` 调整为 `--cov-fail-under=81`。这是对齐当前真实基线，避免假红；后续应另起 coverage uplift 专项逐步拉高。

### 2.6 《<example-project>》项目状态修复

用 `state update --set-hook-close` 回填：

- Ch4：`primary=决策钩`，`source_narrative_version=v3`
- Ch6：`primary=决策钩`，`source_narrative_version=v5`

修复后：

```json
"no_decision_hook_8": false,
"last_8_primaries": ["情绪钩","决策钩","动作钩","动作钩","情绪钩","信息钩","信息钩","信息钩"]
```

## 3. 质量意义

这次修的是“读者爽感闭环”的底层可信度。

如果正文已经写出“明天两件事”“去敲蓝铁门”这种主角主动选择，但 state 仍显示信息钩，下一章 context-agent、reader-pull、audit 和 plan 都会误判作品仍缺决策钩，进而错误地驱动后续章节。修复 H28 后，流程不会再把旧章末当成真相。

这对“写很多潜在读者喜欢看的小说”是必要修复，因为网文读者追读的关键不是工艺分，而是：

- 主角是否主动
- 金手指是否兑现
- 标题承诺是否推进
- 每章是否有可感知的胜利/选择/信息优势

这与 2024-2025 行业趋势一致：网络文学精品化、IP 化、短剧化和跨媒介改编继续强化“故事思维”和强反馈阅读体验。
