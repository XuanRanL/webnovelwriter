### 2.1 polish_cycle 自动 hook_close 同步（核心闭环根治）

`webnovel-writer/scripts/polish_cycle.py`

```python
# update_state_after_polish 末尾新增：
hook_close = meta.setdefault("hook_close", {})
hook_close["text_excerpt"] = _extract_chapter_tail_excerpt(text)
hook_close["source_narrative_version"] = new_version
```

## 4. 这一轮真正解决了什么——对小说质量的意义

读者追读不靠工艺分，靠四件事：
1. **主角是否主动**（决策钩）
2. **金手指是否兑现**（thrill.golden_finger_release）
3. **标题承诺是否推进**（thrill.title_promise_payoff）
4. **每章是否有可感知的胜利/选择/信息优势**（thrill.protagonist_victory + info_advantage）

Round 20.5 修了 H25/H28 在"检测层"工作，但 Round 20.6 这次修的是**"产生层"**——让 polish 不可能再产生未刷新的 hook_close。

具体小说质量影响：

- **Ch3 实际就是决策钩**，但旧记成信息钩。下章 plan 之前会以为"作品长期缺主角主动"，过度补偿、推动剧情走得太冲。修正后下章 plan 拿到准确信号——Ch3/Ch4/Ch6 三章决策钩，节奏没塌，可以稳推 Ch13 的<golden-finger-space> medium 出货+主动博弈。
- **polish_cycle 自动同步 + 强制重分类**：以后任何 polish 改动章末，AI/作者必须 30 秒内重新读章末分类钩子。这强迫每次 polish 都"以读者爽感视角看一遍章末"，而不是只盯子维度分数。这一步直接把"工艺分驱动 polish"改成了"读者爽感驱动 polish"。
- **H21 override 修复**：Ch3 是空间种田激活章，对话占比天生低（主角独自催种），之前被 hygiene 误报让人焦虑要"硬塞对话凑比例"——这正是网文最 AI 味的写法。修复后该豁免就豁免，不再制造虚假压力。

## 5. 剩余风险（不阻断 Ch13）

1. **Ch1/Ch5 H21_no_x 签名过载**（30/29 次）：作者签名签名风格保留，作为"长期改写池"非强制项。

3. **H11 老报告 overall_score 多次出现**（Ch1/Ch10）：旧审查报告字符串冗余，不影响数据。
4. **state_manager.py coverage 67% / webnovel.py 54%**：下章不阻断，但应起 coverage uplift 专项把 81% → 85%。
5. **Round 20.3 thrill manual evaluator**（Ch2/3/4/6）：下次有窗口应真跑 reader-thrill-checker 替代 manual 估值。
6. **真人读者校准未接入**：5-7 章后有目标读者样本时，应做一次 LLM thrill vs 真实读者追读分校准。
